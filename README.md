# LoveHeartBeat

Multi-tenant observability SaaS for **API monitoring**, **API / AI gateways**, **AI tool usage & cost**, **ETL/ELT pipelines**, **alerts**, and **multi-cloud monitoring & cost** (AWS, GCP, Azure).

Product by **RootVyana**. Design target: shared platform for ~**30,000 organizations** (trial → enterprise).

---

## How the system fits together

```text
                    ┌─────────────────────────────────────────┐
                    │  Tenant URL                             │
                    │  https://<slug>.loveheartbeat.com       │
                    └───────────────────┬─────────────────────┘
                                        │
          ┌─────────────────────────────┼─────────────────────────────┐
          ▼                             ▼                             ▼
   ┌─────────────┐              ┌──────────────┐              ┌──────────────┐
   │  Frontend   │  REST/JSON   │   Backend    │  events/    │  Middleware  │
   │  (Pug/JS)   │─────────────▶│  AWS Lambda  │◀────────────▶│  ETL / ELT   │
   │  + Browser  │  X-Tenant-   │  + API GW    │  schedules   │  pipelines   │
   │  Sync/CDN   │  / JWT       │              │              │              │
   └──────┬──────┘              └──────┬───────┘              └──────┬───────┘
          │                            │                             │
          │                     org_id scoped                        │
          │                            │                             │
          └────────────────────────────┼─────────────────────────────┘
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │  External systems (per organization)    │
                    │  Cloud · API gateways · AI tools · ETL  │
                    │  IdP (Okta / SSO) · native login        │
                    └─────────────────────────────────────────┘
```

| Layer | Folder | Role |
|--------|--------|------|
| **Frontend** | `src/`, `public/` (build output) | UI: dashboards, org onboarding, tables |
| **Integration** | `integration/` | Browser API client → backend (tenant-aware) |
| **Backend** | `backend/` | Python Lambdas: APIs, tenant resolve, CRUD |
| **Middleware** | `middleware/` | Batch ETL/ELT jobs (extract → transform → load) |

All reads/writes are scoped by **`org_id`** after the tenant is resolved from the slug subdomain (or `X-Tenant-Slug` in local/dev).

## Multi-tenant model

Each organization is a tenant:

| Concept | Example |
|---------|---------|
| Org name | RootVyana |
| Slug | `rootvyana` |
| Hostname | `https://rootvyana.loveheartbeat.com` |
| Isolation | Members, SSO, cloud accounts, AI/ETL connectors, alerts, billing |

**Auth (per org):**

1. **Okta / SSO** (SAML / OIDC) — enterprise  
2. **LoveHeartBeat login + password** — trials / smaller teams  
3. Optional **mixed mode** (SSO employees + native guests)

**UI entry points:** Organization → Organizations, Multi-tenant, Onboarding, Members, Authentication SSO.

**Backend entry points:** `backend/shared/tenant.py` resolves Host / `X-Tenant-Slug` → `org_id`.

## Frontend

### What it is

Static admin UI (Phoenix theme) compiled with Gulp:

| Source | Becomes |
|--------|---------|
| `src/pug/` | `public/**/*.html` |
| `src/scss/` | `public/assets/css/` |
| `src/js/` | `public/assets/js/` |
| npm vendors (`vendors.json`) | `public/vendors/` |

**Do not commit** compiled HTML/CSS/JS/vendors — they are gitignored and regenerated by Gulp.

### Main product areas (left nav)

**Observability**

- API Monitoring, **API Gateway** (AWS API Gateway, Azure APIM, GCP Apigee)
- AI Monitoring, **AI Gateway** (Claude, Cursor, ChatGPT, Copilot, …)
- ETL Monitoring (Talend, Boomi, dbt, Glue, Fabric, …)

**Organization (SaaS)**

- Organizations, Multi-tenant overview, Onboarding, Members, Authentication / SSO

Tables use shared search / filter / sort / pagination (`src/pug/mixins/observability/Common.pug`).

## Integration layer (`integration/`)

Bridge between the browser UI and backend APIs.

| File | Purpose |
|------|---------|
| `integration/api-client.js` | `fetch` wrapper; attaches tenant; CRUD helpers |

### Tenant-aware requests

```js
import { api, currentTenantSlug, tenantUrl } from './integration/api-client.js';

// Production: slug from hostname  →  acme.loveheartbeat.com
// Local: window.__TENANT_SLUG__ or localStorage `lhb_tenant_slug`

await api.health();
await api.tenant();           // GET /tenant
await api.organizations();    // GET /organizations
await api.list('alerts');
```

Configure before load (or edit defaults in the file):

```html
<script>
  window.__API_BASE_URL__ = 'https://api.loveheartbeat.com';
  window.__TENANT_SLUG__ = 'rootvyana';           // local only
  window.__TENANT_BASE_DOMAIN__ = 'loveheartbeat.com';
</script>
```

Every request sends **`X-Tenant-Slug`** when a slug is known so Lambda can resolve `org_id` without relying only on DNS in local/dev.

## Backend (`backend/`) — AWS Lambda

Python handlers behind API Gateway (or Function URL). Stateless; tenant on every call.

| Path | Purpose |
|------|---------|
| `handlers/health.py` | Health check |
| `handlers/example.py` | Sample CRUD-style handler |
| `handlers/organizations.py` | Tenant context, list orgs, onboard stub |
| `shared/tenant.py` | Host / header → slug → `org_id` |
| `shared/response.py` | JSON + CORS responses |
| `events/` | Sample API Gateway events |
| `requirements.txt` | `boto3`, `pydantic`, … |

### Tenant resolution order

1. `Host: <slug>.loveheartbeat.com`  
2. Else `X-Tenant-Slug` header (local clients)  
3. Lookup slug → org record (demo map today; DynamoDB/Postgres in production)

### Local smoke tests

```bash
cd backend
pip install -r requirements.txt
PYTHONPATH=. python -c "
from handlers.organizations import tenant_context_handler, list_organizations_handler
print(tenant_context_handler({'headers': {'Host': 'rootvyana.loveheartbeat.com'}}, None))
print(list_organizations_handler({}, None))
"
```

### Deploy sketch (production)

1. Package handlers + `shared/` for Lambda  
2. API Gateway HTTP API → routes (`/health`, `/tenant`, `/organizations`, …)  
3. Custom domain / wildcard `*.loveheartbeat.com` so Host carries the slug  
4. Persist orgs/members/connectors in a data store keyed by `org_id`  
5. Wire IdP callbacks per org (Okta / SAML / OIDC) or native auth service

## Middleware (`middleware/`) — ETL / ELT jobs

Batch and sync pipelines that pull from external systems, normalize, and load into LoveHeartBeat (or a warehouse) **per tenant**.

```text
extractors/  →  transformers/  →  loaders/
     │                │               │
  APIs, S3, DB    clean/reshape    stdout / S3 / DB / Lambda
```

| Path | Purpose |
|------|---------|
| `pipelines/` | Runnable jobs (compose E → T → L) |
| `extractors/` | Sources (CSV, later APIs/S3) |
| `transformers/` | Normalize / enrich |
| `loaders/` | Destinations |
| `sample_data/` | Local fixtures |

### Run the example pipeline

```bash
cd middleware
pip install -r requirements.txt
PYTHONPATH=. python -m pipelines.example_pipeline
```

### How middleware ties to the product

| Observability area | Middleware role |
|--------------------|-----------------|
| ETL Monitoring | Ingest run status from Talend, Boomi, dbt, Glue, Fabric, … |
| Cloud / cost | Pull CUR / billing exports multi-account |
| AI cost & usage | Pull provider usage (OpenAI, Anthropic, …) |
| Alerts | Emit anomalies into alert store / SNS |

Jobs should always receive **`org_id` / slug** (env, event payload, or Step Functions input) and never mix tenant data.

**Runtime options later:** Lambda, Step Functions, ECS, Glue, EventBridge schedules.

## External system integrations

Connectors are **owned by the organization**. Frontend surfaces them; backend stores credentials/config (secrets manager); middleware and Lambdas sync metrics.

### Cloud & API gateways

| System | Used for |
|--------|----------|
| AWS (multi-account / Organizations) | Cloud monitoring, cost, API Gateway |
| Azure (subscriptions) | Cloud monitoring, cost, API Management |
| GCP (projects) | Cloud monitoring, cost, Apigee |

### AI tools (monitoring + AI Gateway routing)

Claude, Cursor, ChatGPT / OpenAI, Grok, Lovable, BabyLoveGrowth, DeepSeek, GitHub Copilot, Microsoft Copilot, Gemini, Mistral, …

### ETL / ELT platforms

Talend, Dell Boomi, Jundago, Qlik, Informatica, Alteryx, dbt, SnapLogic, AWS Glue, Microsoft Fabric, Airflow, Fivetran, …

### Identity

| Mode | Integration |
|------|-------------|
| SSO | Okta, Azure AD / Entra, Google Workspace, generic SAML/OIDC |
| Native | LoveHeartBeat email/password (+ MFA policies) |

Integration pattern:

1. Org admin connects a source in UI (Cloud Monitoring, AI Monitoring, Auth, …)  
2. Backend stores connector metadata + secret refs under `org_id`  
3. Middleware / scheduled Lambdas pull data and write tenant-scoped metrics  
4. Frontend reads via `integration/api-client.js` → backend APIs

## Security notes

- Do not commit cloud API keys, Mapbox tokens, or IdP secrets (use env / Secrets Manager).  
- Compiled `public/**/*.html`, `public/assets/css|js`, `public/vendors`, and `node_modules` are gitignored.  
- Always authorize against the resolved `org_id`; never trust client-supplied org alone without token claims.
